# Batch Searching for Play Log Details

Source: [api-189311783.md](../../api/api-189311783.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web. **Use:** Request batch playback detail reports.

## Useful facts

- **`POST /v2/logs/play-logs/batch-detail`** — Request batch playback detail reports.
- Advanced API permission is required. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Target at most 100 player IDs. Only one play-log search task may run at a time for an organization user; wait for completion before submitting another.
- Searches cover the past 3 months, with at most 7 consecutive days per request. `startDate` is included; `endDate` is excluded.
- The initial response returns `taskId`. A later POST JSON callback supplies task ID, record count, Excel download URL and status (`2` success, `3` failure).
- Return the literal string `ok` from the callback within 3 seconds; otherwise the service retries.
- The generated Excel file is retained for 7 days, then deleted. Full request and callback schemas are in the source.

## App implications and unknowns

Queue export requests across the organization and save reports before expiry. Use named media/widgets to reconcile app campaigns; the source does not define the Excel columns or guarantee physical screen visibility. Batch detail has a 7-day limit, unlike the 30-day single-player detail and overview APIs.
