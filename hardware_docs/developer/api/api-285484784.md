# Scheduled Restart Players

Source: [api-285484784.md](../../api/api-285484784.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Schedule player restarts.

## Useful facts

- **`POST /v2/player/scheduled-control/reboot`** — Schedule player restarts.
- Advanced API permission is required. Sub-accounts are limited to their workgroup and its descendants. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Maximum 100 players. Passing an empty `schedules` array clears all schedules for this control.
- Plans use date bounds and `execTime` in `HH:MM:SS`, evaluated in the player’s local time. Weekdays use Sunday `0` through Saturday `6`; absent/empty `weekDays` executes daily within the date range.
- Each plan defines the time of a reboot; no reboot duration or subsequent recovery callback is provided.
- The immediate response separates `success` and `fail`; no callback confirms future execution. Full fields are in this endpoint and the [Scheduled plan item](schema-161188704.md).

## App implications and unknowns

Store device time zones alongside schedules and show pending/failed updates per player. Confirm replacement/conflict and daylight-saving behavior; an accepted schedule does not prove its later action occurred.
