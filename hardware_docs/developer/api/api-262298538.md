# Screen list

Source: [api-262298538.md](../../api/api-262298538.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Discover screens registered for Care monitoring.

## Useful facts

- **`GET /v2/device-status-monitor/screen/list`** — Discover screens registered for Care monitoring.
- Advanced API permission is required. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- `pageNumber` and `pageSize` are required; page size is 1–1000. Optional filters cover status, name and address.
- Status codes are `1` normal, `2` offline, `3` risky, `4` faulty. These differ from Media player online-status codes.
- Returns `total` and screen items directly, including `sid`, serial number, address/coordinates, camera presence and brightness. Ambient brightness `-1` means unavailable.
- Camera presence is `0` no / `1` yes. No callback or guarantee that coordinates are live GPS is stated.

- The schema permits `pageNumber` from 0; confirm the first-page convention rather than copying the brightness-history pagination.

## App implications and unknowns

Map Care screen SID/SN separately from Media player ID. Treat coordinates as reported screen metadata until their origin and refresh behavior are verified.
