# Notes

Source: [doc-4696871.md](../../api/doc-4696871.md) - Notes, items 1–4 and Enumeration information table. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Interpret hardware position and alarm location codes.

## Useful facts

- **Notes, items 1–3:** positions are grouped in four-character segments identifying device type and index; alarm positions append a physical-status segment.
- The examples traverse screen, sending card, Ethernet port, receiving card, monitor card and smart-module coordinates. Hexadecimal letters occur in codes.
- **Enumeration information table:** device and physical-status codes are separate tables; status categories include voltage, temperature, fan, smoke, input, cabinet door, cable, redundancy and connection.
- Smart-module coordinate examples describe encoded `00` as coordinate 1; do not apply one global indexing offset to all segments.

## App implications and unknowns

Use these codes to label fault locations within an LED screen. They are unrelated to truck GPS. Preserve raw values alongside decoded labels because the tables do not specify every possible vendor extension.
