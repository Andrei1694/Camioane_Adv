# Searching for the Play Log Overview of a Single Player

Source: [api-189316709.md](../../api/api-189316709.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web. **Use:** Request single-player playback overview reports.

## Useful facts

- **`GET /v2/logs/play-logs/single-summary`** — Request single-player playback overview reports.
- Advanced API permission is required. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Target one player ID using the documented query parameters. Only one play-log search task may run at a time for an organization user; wait for completion before submitting another.
- Searches cover the past 3 months, with at most 30 consecutive days per request. `startDate` is included; `endDate` is excluded.
- The initial response returns `taskId`. A later POST JSON callback supplies task ID, record count, Excel download URL and status (`2` success, `3` failure).
- Return the literal string `ok` from the callback within 3 seconds; otherwise the service retries.
- The generated Excel file is retained for 7 days, then deleted. Full request and callback schemas are in the source.

## App implications and unknowns

Queue export requests across the organization and save reports before expiry. Use named media/widgets to reconcile app campaigns; the source does not define the Excel columns or guarantee physical screen visibility. Do not apply vendor UI batch-count limits to this API.
