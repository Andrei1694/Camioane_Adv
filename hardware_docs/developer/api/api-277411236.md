# Program Over-specification Detection

Source: [api-277411236.md](../../api/api-277411236.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Check a program against target player specifications.

## Useful facts

- **`POST /v2/player/program/over-specification-check`** — Check a program against target player specifications.
- This page does not state a basic/advanced permission tier. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Send player IDs and pages/widgets with media metadata. The response groups players by `overSpec` and supplies page/widget-specific failures and recommended conversion dimensions/bitrate.
- The page states an image limit of width ≤2160, height ≤4096 and area ≤2160×4096. This orientation differs from the TB60 specification tables; retain it as this API’s stated rule, not a replacement device limit.
- Failures distinguish unsupported codecs/containers, dimensions, frame/bit rates, channel/window count, memory and playback/restart problems. Link to `overSpecErrorCode` rather than copying its full list.
- The response is direct (`logid`, `status`, `data`); no callback is documented. The schema does not explain the top-level status values.
- Video-only fields are described as conditional but all appear in the required widget list; bitrate is described ambiguously as “large M”.

## App implications and unknowns

Use this as an additional preflight check, not a transcoding service or playback guarantee. Confirm bitrate units, conditional fields and device-specific limits before constructing requests.
