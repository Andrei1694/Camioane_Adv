# Receiving cards — monitoring

Source: [api-181820139.md](../../api/api-181820139.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Read receiving-card health, temperature and voltage.

## Useful facts

- **`GET /v2/device-status-monitor/receiving-card/monitor/{sn}`** — Read receiving-card health, temperature and voltage.
- Advanced API permission is required. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Query by device `sn`; each item includes card position and serial number. `deviceWorkState`: `true` normal, `false` abnormal.
- This is a direct HTTP response, not a push subscription. Monitoring requires VNNOX Care binding; availability depends on the installed device and reporting hardware.
- Temperature/voltage units and data freshness are not specified on this page; retain the source field meanings until confirmed.

- The schema names the state `deviceWorkState`, but the example uses `status`. Confirm the actual field before building a parser.

## App implications and unknowns

Display unavailable readings distinctly from healthy values. Join positions using the [location-code reference](doc-4696871.md); the endpoint cannot establish that an advertisement was visible.
