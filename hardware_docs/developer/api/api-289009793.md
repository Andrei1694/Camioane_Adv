# Screen detail

Source: [api-289009793.md](../../api/api-289009793.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Read aggregate Care details for multiple screens.

## Useful facts

- **`POST /v2/device-status-monitor/all`** — Read aggregate Care details for multiple screens.
- Advanced API permission is required. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- `snList` accepts at most 10 serial numbers, unlike the larger Media command batches.
- The direct `value` response combines screen, controller, input-source, receiving-card, module, monitoring-card and smart-module data, including topology and alarms.
- Nested fields inherit missing-data caveats for LCT590/Mbox V1.3+; ambient brightness `-1` means unavailable and smart-module runtime is stated in minutes.
- The aggregate receiving-card monitor uses `status`, while the [standalone endpoint](api-181820139.md) uses `deviceWorkState`. Do not assume all nested shapes match their standalone versions.
- No callback, refresh interval or guarantee of installed sensing hardware is given.

- Other nested types also differ from standalone schemas, and the example uses placeholder objects for many scalar fields. Validate the aggregate contract independently.

## App implications and unknowns

Use batches of 10 for an optional diagnostics view, with null/unsupported states. Preserve the distinction between hardware health, online connectivity and actual advertisement playback.
