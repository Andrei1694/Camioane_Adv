# Player Common Solution

Source: [schema-162442578.md](../../api/schema-162442578.md) - OpenAPI Specification → components.schemas.Player Common Solution. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Structure normal solutions, page schedules and typed widgets.

## Useful facts

- **Player Common Solution schema:** requires player IDs (maximum 100) and pages. Each page has a name and widgets.
- Empty program/page scheduling means continuous looping; when both schedules exist, playback uses their intersection. Weekday numbers are Sunday `0` to Saturday `6`.
- Widget payloads vary by type; media uses lowercase MD5, bytes, valid URL, millisecond duration and percentage layout. Specialized alternatives describe weather, sensors and clocks.
- Optional `noticeUrl` receives download progress and must respond within 3 seconds; the [publishing endpoint](api-180502121.md) contains the callback details.
- The schema is incomplete for some listed types, using an open object fallback. Page-level `weekDays` is typed string despite array examples; clock weekday order and weather `unitSymbol` types also conflict with examples.

## App implications and unknowns

Use this as a source map, not an unquestioned generated validator. Confirm inconsistent fields and keep app campaign identity separate from vendor page/widget names; permissions and download/playback distinction follow the publishing endpoint.
