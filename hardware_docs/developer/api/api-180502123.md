# Canceling Emergency Insertion Solutions

Source: [api-180502123.md](../../api/api-180502123.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Cancel the currently playing emergency insertion.

## Useful facts

- **`POST /v2/player/emergency-program/cancel`** — Cancel the currently playing emergency insertion.
- Advanced API permission is required. Sub-accounts are limited to their workgroup and its descendants. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Maximum 100 player IDs per request.
- The response separates `success` and `fail` player IDs; successful sending does not establish device execution. No completion callback is specified here.
- The operation is described as canceling the insertion currently playing; it does not define removal of future timed insertions.

## App implications and unknowns

Do not present this as clearing all emergency schedules. Confirm the current solution after canceling and handle each failed player independently.
