# Receiving cards — topology

Source: [api-198265532.md](../../api/api-198265532.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web. **Use:** Read receiving-card topology and Ethernet redundancy.

## Useful facts

- **`GET /v2/device-status-monitor/receiving-card/topology/{sn}`** — Read receiving-card topology and Ethernet redundancy.
- Advanced API permission is required. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Query by device `sn`; returns controller information, receiving-card positions/dimensions and primary/redundant port relationships.
- Fields include sender/port/connection indices and `physicalDataKey`; the original schema preserves spellings such as `redus` and `topologys`.
- This returns data directly, with no callback, map-editing or hardware-write operation.

## App implications and unknowns

Use only for a support diagram when the installation reports topology through Care. Pixel positions are within the LED screen, not geographic coordinates; exact mapping still comes from the installer.
