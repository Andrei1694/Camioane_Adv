# Monitoring cards — monitoring

Source: [api-198270522.md](../../api/api-198270522.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Read monitoring-card sensor and cabinet status.

## Useful facts

- **`GET /v2/device-status-monitor/monitor-card/monitor/{sn}`** — Read monitoring-card sensor and cabinet status.
- Advanced API permission is required. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Query by device `sn`; data includes working state, cabinet door, smoke, flat-cable status, up to nine fan channels and nine voltage channels.
- `socketCableStatus` returns empty for the source’s “LCT590 and Mbox V1.3 or above” configurations.
- The HTTP response is direct. Channel availability, most units and boolean interpretation beyond field names are not explained on this page.

- The example uses `-255` for many fan/voltage channels without defining that sentinel. Do not display it as a real measurement without clarification.

## App implications and unknowns

Requires installed monitoring hardware and Care reporting. Keep missing channels distinct from zero or healthy values; decode hardware [position codes](doc-4696871.md) when showing faults.
