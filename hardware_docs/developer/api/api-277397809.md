# Offline Export

Source: [api-277397809.md](../../api/api-277397809.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Export an offline program in Nova playback protocol.

## Useful facts

- **`POST /v2/player/program/offline-export`** — Export an offline program in Nova playback protocol.
- This page does not state a basic/advanced permission tier. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Support is documented for T cards V2.0.0+ and vPlayer V4.0.0+. This exports protocol files; it does not directly send them to a player.
- `programType` is `1` (normal program); `planVersion` selects `V1`/`V2`. For multiline text, the source specifies V2 when T firmware is greater than 3.10.0.0601 or V firmware greater than 4.1.1.0601.
- Program/page schedules intersect; an empty schedule means continuous looping. Widget definitions are in the [component references](folder-53325354.md).
- The response directly returns protocol-file descriptors (MD5, filename, URL) for display/play solutions, relations, playlists, constraints and plan JSON; no completion callback is defined.
- `schedule` is marked required despite the empty-schedule description; `plans` is modeled as an object here, unlike the array in [Player Common Solution](schema-162442578.md).

## App implications and unknowns

Confirm the export shape and V1/V2 boundary on the installed firmware. Download lifetime, packaging, media transfer and local import/authentication require further documentation; this is not a substitute for the Taurus local SDK.
