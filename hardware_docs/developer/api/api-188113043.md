# Controller — operating parameters

Source: [api-188113043.md](../../api/api-188113043.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Read controller operating settings and resources.

## Useful facts

- **`GET /v2/device-status-monitor/master-control/running/{sn}`** — Read controller operating settings and resources.
- Advanced API permission is required. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Query by device `sn`; groups cover memory/storage/CPU, playback/display, network, RF, clock, sensor, volume, video source and schedules.
- Network type codes distinguish no network, wired, Wi-Fi and 2G/3G/4G. This schema does not define a 5G code.
- Many playback, RF, schedule, sensor, clock and video fields are documented as empty for “LCT590 and Mbox V1.3 or above”.
- `lora.existLora` is oddly described as detection of a 4G module. Preserve literal wire keys such as `rebotConfig` and `sourceTpye`; do not infer RF/cellular capability from this description.
- This is a direct HTTP response, not a push subscription. Monitoring requires VNNOX Care binding; availability depends on the installed device and reporting hardware.

## App implications and unknowns

Use this for diagnostics with explicit unknown/unsupported states. Units, reporting cadence and ambiguous RF fields need supplier confirmation; these are observations, not a settings-write API.
