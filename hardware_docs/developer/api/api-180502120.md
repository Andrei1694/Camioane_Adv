# Screenshots

Source: [api-180502120.md](../../api/api-180502120.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web, mobile. **Use:** Request a screenshot from selected players.

## Useful facts

- **`POST /v2/player/real-time-control/screen-capture`** — Request a screenshot from selected players.
- Advanced API permission is required. Sub-accounts are limited to their workgroup and its descendants. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Maximum 100 player IDs; `noticeUrl` is required.
- The immediate response reports IDs successfully/unsuccessfully sent. The screenshot arrives later by POST JSON to `noticeUrl`; the receiver must respond within 3 seconds.
- The callback schema supplies `playerId`, `playerTime` and `screenShotUrl`; the URL is valid for 2 hours and the source says to download it to your server within that period. Callback authentication is not specified.

## App implications and unknowns

Correlate screenshots to player and capture time. A screenshot shows one moment, not continuous playback or physical panel visibility. Archive required screenshots within the two-hour window and confirm callback verification.
