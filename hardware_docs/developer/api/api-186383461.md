# Obtaining Control Command Execution Logs

Source: [api-186383461.md](../../api/api-186383461.md) - OpenAPI Specification: operation description, request/response schemas and examples. Unversioned API snapshot retrieved 2026-11-10.

**Audience:** Backend, web. **Use:** Read control-command execution history for one player.

## Useful facts

- **`GET /v2/logs/remote-control`** — Read control-command execution history for one player.
- Advanced API permission is required. Sub-accounts are limited to their workgroup and its descendants. Apply the [Access Guide](doc-4696857.md) authentication and account prerequisites.
- Query one `playerId` and a command `taskType`; pagination uses `start` (default 0) and `count` (default 20, range 1–100). Supported task categories include reboot, display/source/sync, upgrades, screenshot, time zone, power, volume and brightness.
- Returns `total`/`rows` directly; execution status is documented as `0` unknown, `1` successful, `2` failed, with execution time and command type.
- The OpenAPI export unusually defines a JSON request body on GET, conflicting with the [Access Guide](doc-4696857.md) GET guidance. `status` is typed string but the example is numeric; the `setVolume` description also says time zone.

## App implications and unknowns

Confirm parameter transport and status type before generating a client. This supports command confirmation; it is not a record of media playback. Retention and timestamp zone are unspecified.
